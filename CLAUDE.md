# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Rust SDK for the Langfuse LLM observability API. Async, built on `reqwest` + `tokio`, with a blocking client behind the `blocking` feature. Targets Rust 1.99+ (edition 2024). The SDK implements all 120 operations of `openapi.yml`; the 21 `/api/public/unstable/*` operations are behind the `unstable` Cargo feature. Native tracing on OpenTelemetry (`src/otel/`) is behind the `otel` feature, and so is `run_experiment`; datasets with items, evaluators and batch evaluation work without it. Features building on `otel`: `macros` (`#[observe]`, from the workspace crate `macros/` = `langfuse-rust-sdk-macros`, published first and pinned with `=x.y.z`), `tracing-layer` (bridge from the `tracing` crate) and `openai` (traced `async-openai` 0.43).

## Build & Test Commands

```bash
cargo build                                # Build the library
cargo test                                 # All tests without optional features (504)
cargo test --all-features                  # Every feature (659; includes the trybuild UI tests)
cargo test --test api_scores_tests         # One wiremock test file
cargo test --test serde_tests              # Serialization tests of the original models
cargo test --lib                           # In-crate unit tests (retry, http, config from_env, ids, prompt templates, prompt_cache, yaml_tool, experiment format, batch filters; --features otel adds experiment IDs and Python JSON)
cargo clippy --all-targets --all-features -- -D warnings
cargo run --example health_check           # Example against the real API (needs .env)
cargo run --example dashboards --features unstable  # Examples of unstable APIs need the feature
cargo test --features otel --test otel_tests          # Tracing tests (exported OTLP bodies checked with wiremock)
cargo test --features otel --test experiment_tests    # run_experiment (span tree, attributes, scores)
cargo run --example otel_tracing --features otel      # Tracing example against the real API
cargo run --example otel_export_options --features otel # Gzip export, shared provider and mask_otel_spans against the real API (deletes its trace)
cargo run --example run_experiment --features otel    # Experiment against the real API (deletes its data)
cargo test --features macros --test observe_tests     # #[observe] (OTLP bodies); observe_ui_tests: compile errors
TRYBUILD=overwrite cargo test --features macros --test observe_ui_tests  # Regenerate tests/ui/observe/*.stderr
cargo test --features openai --test openai_tests      # OpenAI wrapper against a wiremock fake OpenAI
cargo test --features tracing-layer --test tracing_layer_tests  # tracing bridge with real rig-core/rig-agent spans
cargo test --features blocking --test blocking_tests  # Blocking client (mock server on its own runtime)
python3 scripts/generate_blocking.py       # Regenerate src/blocking/api.rs after changing an API client
```

Tests never touch the network. HTTP behaviour is tested with `wiremock` in `tests/api_*_tests.rs`; shared helpers live in `tests/common/mod.rs` (`test_client()`, `test_client_with_retries(n)`, `json(status, body)`, `single_request`, `body_json`/`body_bytes` (gunzip bodies sent with `Content-Encoding: gzip`, as OTLP exports are by default), `query_pairs`, `query_value`). Client helpers (`Clone`, `auth_check`, `trace_url`, custom `reqwest::Client`) are tested in `tests/client_tests.rs` the `*_pages` streams in `tests/pagination_tests.rs` (which consumes them with the `futures` dev-dependency), prompt compilation in `tests/prompt_compile_tests.rs` and `get_cached` in `tests/prompt_cache_tests.rs` (timing-based: short TTLs and delayed mocks, polled with bounded waits). Test files for unstable APIs start with `#![cfg(feature = "unstable")]`; the score queue is tested in `tests/score_queue_tests.rs` and media in `tests/media_tests.rs` (presigned URLs point at the mock server); `tests/otel_tests.rs` starts with `#![cfg(feature = "otel")]`, builds tracers with `flush_interval` of one hour and parses the OTLP/JSON bodies posted to `/api/public/otel/v1/traces` (it also covers compression, export path, `mask_otel_spans`, ID generator, custom exporter, `with_provider` with an in-memory `MemoryExporter`, and concurrent media uploads by timing); `tests/experiment_tests.rs` does the same for `run_experiment` (and mocks `GET /api/public/projects` and `POST /api/public/scores`). `get_dataset`/`create_dataset_item` are tested in `tests/dataset_tests.rs` and `run_batched_evaluation` in `tests/batch_evaluation_tests.rs`. `with_options` is tested in `tests/request_options_tests.rs`; skills discovery in-crate (`src/skills.rs`, temp directories, explicit working directory) and its span attributes in `tests/otel_tests.rs`. `tests/observe_tests.rs` (`macros`) touches the global tracer in one test only; `tests/openai_tests.rs` (`openai`) runs async-openai against a second wiremock server (SSE bodies for streams); `tests/tracing_layer_tests.rs` (`tracing-layer`) uses the dev-dependencies `rig-core`/`rig-agent` against a fake OpenAI; `tests/blocking_tests.rs` (`blocking`) uses plain `#[test]`s and checks that every public method of `src/api` has a blocking wrapper. Examples in `examples/` hit the real Langfuse API; each doc comment says whether it writes data and how it cleans up. Examples using unstable APIs are declared in `Cargo.toml` with `required-features = ["unstable"]`. Examples build their client with `ClientConfig::from_env()` and need `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL` via `.env` or environment.

## Architecture

**Entry point:** `LangfuseClient` in `src/lib.rs` (`#[non_exhaustive]`, `Clone`) — constructed from a `ClientConfig`, it holds one sub-client per resource group (all `Clone`), each wrapping a shared `Arc<HttpClient>`, plus the helpers `auth_check()` and `trace_url()` (project ID cached in an `Arc<OnceLock>` shared by clones). Unstable sub-clients (`unstable_dashboard_widgets`, `unstable_dashboards`, `unstable_topics`) are `#[cfg(feature = "unstable")]`.

**Core layers:**

- `src/config.rs` — Builder pattern (`ClientConfig::builder(pk, sk).base_url(...).build()`) or `ClientConfig::from_env()` / `ConfigBuilder::from_env()` (`LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL`/`LANGFUSE_HOST`, `LANGFUSE_TIMEOUT`; tested in-crate through `from_lookup`, never by mutating the process environment). Produces HTTP Basic Auth header, SDK identification headers (`x-langfuse-sdk-name`, `x-langfuse-sdk-version`, `x-langfuse-public-key`). The base URL always ends with `/` and `HttpClient` joins request paths relative to it, so a base path prefix is kept. `http_client(reqwest::Client)` injects a custom client (explicit `timeout()` then applies per request); an invalid `header()` makes `build()` fail. `media_upload_concurrency(n)` / `LANGFUSE_MEDIA_UPLOAD_THREAD_COUNT` (default 1, `0` fails) sets the uploads the media queue runs at once.
- `src/http.rs` — `HttpClient` (an `Arc<Shared>` with the `reqwest::Client`, base URL, auth, default headers and retry policy, plus the view's `RequestOptions`) wraps `reqwest::Client`. One private `execute` loop handles auth, headers (default < per-call `CallOptions` < view, replacing by name), query (serialized once with `serde_urlencoded`; view parameters replace same-named ones), JSON body (view `body` fields merged into objects), the `response_hook` and retries. Precedence of timeout/retries: crate-private `CallOptions` (set by `get_cached`, batch evaluation, ingestion, score queue) > view > client. `CallOptions::gzip` (feature `otel`, set by `IngestionClient::export_traces`) compresses the JSON body once with `flate2` and adds `Content-Encoding: gzip`. `LangfuseClient::with_options` builds a view with `HttpClient::with_options` and `assemble` (shared prompt cache, project ID, background). Public helpers:
  - JSON response: `get`, `get_with_query`, `post`, `put`, `patch`, `delete_with_response` (no body), `delete_with_body_response` (JSON body).
  - Body ignored (204 and similar): `post_no_response`, `post_no_response_with_headers`, `patch_no_content`, `delete_no_content`, `delete_no_content_with_query`, `delete_with_body`.
  - `encode_path_segment` (crate-private): percent-encode every interpolated path parameter (`folder/name` → `folder%2Fname`). Always use it when building paths.
- `src/retry.rs` — `RetryPolicy` with exponential backoff + jitter. Honors `Retry-After`. Retries depend on idempotency (`HttpClient` decides from the method, GET/HEAD/PUT/DELETE/OPTIONS, unless the crate-private `CallOptions::idempotent` overrides it, as OTLP ingestion does): 408, 429, 503 and connection failures are retried for every request; other 5xx, timeouts and dropped connections only for idempotent ones (`RetryPolicy::is_retryable_for`, `http::retry_transport_error`). 409 is never retried. The public `should_retry(status, attempt)` keeps the idempotent, status-only rule.
- `src/error.rs` — `LangfuseError` (`#[non_exhaustive]`) maps status codes to variants: 400, 401, 403, 404, 405, 409 `Conflict`, 412 `PreconditionFailed`, 429 `RateLimited`, 503 `ServiceUnavailable`, other 5xx `ServerError`. `body()` returns the parsed JSON error body.
- `src/pagination.rs` — `Paginated<T>` (page-based, `PageMeta`) and `CursorPaginated<T>` (`CursorMeta`), plus `PageParams` / `CursorParams`. Lazy streams: `paginate_pages` / `paginate_cursor` return `Pages<'a, P>` (boxed, `Send`, `Unpin`); `Pages::items()` returns `Items`. Params implement `PageQuery` / `CursorQuery` through the crate-private `impl_page_query!` / `impl_cursor_query!` macros, invoked next to each params struct.
- `src/skills.rs` — `discover_skills` (port of Python's `_client/skills.py`: sorted immediate subdirectories, `std::fs::metadata` follows links, lexical `absolute` like `os.path.abspath`, lock in the directory else the working directory) and `SkillReference` (`extra` flattened); `serialize_skills` (crate-private) is used by propagation and the tracer.
- `src/ids.rs` — `create_trace_id(seed)` / `create_observation_id(seed)`: random W3C IDs, or `SHA-256(seed)` truncated to 16/8 bytes.
- `src/prompt_cache.rs` (crate-private) — cache behind `PromptsClient::get_cached`: `Mutex<State>` with entries (`Arc<Prompt>` + expiry; expired entries stay readable), the keys being refreshed (claimed through a `RefreshGuard` dropped at the end of the background `tokio` task) and a generation counter bumped by `invalidate`/`clear`, so a fetch that started before an invalidation is not written back. Shared by `PromptsClient` and `PromptVersionClient`; `create`, `delete*` and `prompt_versions.update` invalidate the prompt name. Per-call `max_retries` / `fetch_timeout` go through the crate-private `CallOptions` of `HttpClient` (`get_with_query_options`).
- Prompt compilation lives in `src/models/prompts.rs`: `Prompt::variables`, `compile`, `compile_with_placeholders` (`CompiledPrompt<ChatPromptMessage>`), `compile_with_json_placeholders` (`CompiledPrompt<serde_json::Value>`, keeps extra message fields such as `tool_calls`) and the private `{{variable}}` template engine with its unit tests.

**API clients** (`src/api/`): One file per resource group. Each struct holds `Arc<HttpClient>`; query-param structs live next to the client. API paths use the `/api/public/` prefix.

**Models** (`src/models/`): Request/response structs with serde derives. Key patterns:
- Response structs: `Deserialize` + `#[serde(rename_all = "camelCase")]`; nullable or non-required spec fields are `Option`.
- Request structs: `Serialize`, `skip_serializing_if = "Option::is_none"` on optional fields; structs with many optional fields have a `new(required...)` constructor for use with `..Struct::new(..)`.
- Enums deserialized from responses are declared with the `wire_enum!` macro (`src/models/macros.rs`): `#[non_exhaustive]` plus an `Unknown` variant (`#[serde(other, skip_serializing)]`). Request-only enums are plain `Serialize` enums without `Unknown`. Tagged unions stay strict (no `Unknown`).
- Tagged unions use `#[serde(tag = "...")]` with `#[serde(flatten)]` for shared base fields: `ScoreV3` (`dataType`), `ScoreSubjectV3` (`kind`), `Prompt` (`type`), `Evaluator`/`EvaluatorVersion` (`type`), `EvaluatorOutputDefinition` (`dataType`), `EvaluationRuleFilter` (`type`), `DashboardPlacement` (`type`).
- Constant fields (e.g. `"type": "placeholder"`, `"operator": "in"`) use `#[serde(tag = "...", rename = "...")]` on the struct.
- Wire names that `camelCase` cannot produce need explicit renames: `baseURL`, SCIM `Resources`, `row_limit`, `show_value_labels`, `every_20_minutes`, filter operators with spaces, `orderBy` values with dots.
- JSON-in-query parameters (`filter`, metrics `query`) are `String`s (or typed and serialized with `serde_json::to_string`, as in `MetricsClient::query`). `ListObservationsParams` serializes as key/value pairs so `environment` can repeat.
- Shared types: `evaluation_common.rs` (evaluators + evaluation rules: `Creator`, variable mappings, `PublicApiError`, `EvaluationRuleReadFilter`), `unstable_common.rs` (`UnstablePublicApiError`, `DashboardWidgetFilter`).

**Background work** (`src/background.rs`, crate-private): `Background` (in `LangfuseClient`, `Arc`-shared by clones) lazily spawns two Tokio tasks on first use (`None`/dropped with a log outside a runtime): the score queue (`client.score`; batches by `ScoreQueueOptions` `flush_at`, `flush_interval`, `max_batch_bytes` capped at 1,000,000; sent with `CallOptions { idempotent: Some(true) }` because every queued score has an ID; 207 results logged) and the media upload queue (`LangfuseMedia::upload_with`, up to `media_upload_concurrency` at once in a `FuturesUnordered`; `Flush` waits for those in flight). Workers hold `Arc<HttpClient>` only, so they never keep the client alive. `client.flush`/`shutdown` wait for both.

**Media** (`src/media.rs`): `LangfuseMedia` (bytes in `Arc<[u8]>`, base64 SHA-256, media ID = first 22 chars of the URL-safe hash, `Serialize` as a data URI), `MediaReference`, `MediaTarget`/`MediaField`, and the upload protocol (`get_upload_url` → presigned PUT through `HttpClient::raw_client` without Langfuse credentials, `x-amz-checksum-sha256` + `x-ms-blob-type` except for `storage.googleapis.com`, retried → `patch`). Crate-private detection: `extract_media` is used by `create_dataset_item` and the `otel` exporter; `extract_from_attribute` and `field_for_attribute` only by the exporter, so they carry `cfg_attr(not(feature = "otel"), allow(dead_code))`. `MediaClient::download`/`resolve_references` live in `src/api/media.rs`.

**Tracing** (`src/otel/`, feature `otel`; `opentelemetry`/`opentelemetry_sdk` 0.33, re-exported from `otel`):
- `tracer.rs` — `LangfuseTracer` (`LangfuseClient::tracer`): built on a `LangfuseSpanProcessor`; `new` gives it its own `SdkTracerProvider` (resource `langfuse.environment`/`langfuse.release`, `TraceIdRatioBased` sampler, `AlwaysOff` when disabled, the options' `id_generator` through `SharedIdGenerator`), `with_provider(&processor, provider)` uses a provider the user built with a clone of the processor (error if the processor never got a resource; `shutdown` leaves that provider running). Scope `langfuse-sdk` with attribute `public_key`. `flush`/`shutdown` are async and wait for the export task.
- `observation.rs` — `Observation` holds `Arc<Inner>`: the OpenTelemetry `Context` with the span, plus a `Mutex` buffer of attributes written once at `end` (or when the last handle drops), because the SDK's `set_attribute` appends duplicates and caps attributes per span. `in_scope`/`context()` put a `CurrentObservation` value and the `langfuse_trace_id` baggage claim in the context; `in_scope` builds its context lazily (first poll), as does `propagate_attributes` (an `async fn`), so scopes nest in either order.
- `propagation.rs` — `PropagatedState` (validated, merged) stored as a context value; `inherited_attributes` (state + `langfuse_*` baggage) is applied by the processor in `on_start`. `experiment_context` adds the crate-private `ExperimentAttributes` of `run_experiment`.
- `processor.rs` — public `LangfuseSpanProcessor` (`Clone`, `Arc<Inner>`): `new(&client, options)` validates the options, warns when `OTEL_SDK_DISABLED` is set, spawns the export task (needs a runtime unless disabled) and keeps the `TracerSettings` its tracers use. `on_start` propagation and the app-root mark (`langfuse.internal.is_app_root`), `on_end` filtering (`should_export_span`, foreign-project spans) and non-blocking `try_send` to the export task; the default filters (`is_default_export_span`, ...).
- `exporter.rs` — export task (batches by `flush_at`, `flush_interval`, `max_batch_bytes`) and the `SpanData` → `IngestTracesRequest` conversion (attributes de-duplicated last-wins, grouped by scope), sent with `IngestionClient::export_traces` (crate-private: `traces_export_path`, gzip per `TracingOptions::compression`, idempotent retries). Export pipeline: de-duplicate attributes → `upload_media` (rewrites string attributes holding base64 media into reference strings and queues the uploads, `TracingOptions::media_upload`) → `mask_otel_spans` (batch of `MaskableSpan`, only attributes mutable; a panic drops the batch) → either the custom `SharedSpanExporter` (tokio `Mutex` because `set_resource` takes `&mut`; `force_flush`/`shutdown` forwarded) or the Langfuse endpoint. `options.rs` resolves compression (`LANGFUSE_OTEL_COMPRESSION`, then the two OTel variables, invalid values fall through), the CI release variables and `OTEL_SDK_DISABLED`.
- Scores: `Observation::score`/`score_trace` and `LangfuseTracer::score_current_*` fill trace/observation IDs and the effective environment and call `client.score` (the tracer keeps a `LangfuseClient` clone in `TracerShared`). `LangfuseTracer::score` applies the tracer's sampling to any score (`Sampler::TraceIdRatioBased::should_sample` on W3C trace IDs, same decision as the spans; non-W3C IDs pass; dropped when disabled). `tracer.flush`/`shutdown` export spans first, then flush the client (the export queues media uploads).
- `observe.rs` (module `otel::__observe`, `#[doc(hidden)]`, feature `macros`) — runtime of `#[observe]`: `Observer` (start from the current observation's `shared` tracer, else `LangfuseTracer::global()`; `scope`/`enter`; `finish`; `Drop` = panicked/cancelled), autoref dispatch (`Wrap`, `Capture*`/`Outcome*` traits: calls need one more `&` than the preferred impl's `Self`), `ObservedStream`/`ObservedIter`. The proc-macro (`macros/src/lib.rs`) rewrites the body into `async move` (with the `if false { return fake }` type pin when the return type is nameable) or a closure, rebinds non-identifier parameter patterns, and recognizes `impl Stream/Iterator<Item = T>`.
- `tracing_layer.rs` (feature `tracing-layer`) — `tracing_layer(&tracer)`: `tracing_opentelemetry::layer()` on `provider().tracer("tracing")`, without busy/idle timings.
- `observation.rs` also has `in_trace`/`TraceContext::attach` (remote parent + `RemoteTraceParent` marker, so `Observation::start` sets `as_root`) and `record_error` (level, status, `exception` event). `tracer.rs` holds the global tracer (`install_global`).
- Skills: `PropagatedState` keeps `skills_available` (JSON, never baggage) and `attach_skills`; `LangfuseSpanProcessor::on_start` adds the configured `TracingOptions::skills` (serialized once) when the context attaches them, unless the span has its own or propagated ones, or belongs to another project.
- `attributes.rs` — public attribute keys; input/output as raw strings or compact JSON, metadata flattened to `<prefix>.<key>` with JSON-encoded values, integers beyond 2^53 as strings.

**Datasets, experiments and evaluation:**
- `src/dataset.rs` (crate-private) — `impl LangfuseClient { get_dataset, create_dataset_item }`: every page of dataset items (`GetDatasetOptions` in `api/datasets.rs`, `DatasetWithItems` in `models/datasets.rs`), and media found by `media::extract_media` uploaded (awaited, first field wins, item ID generated) before the item is created.
- `src/experiment.rs` — shared by experiments and batch evaluation: `Evaluation`/`EvaluationValue` (data type follows the value; `to_score_request`), the dyn-compatible `Evaluator`/`CompositeEvaluator`/`RunEvaluator` traits (boxed futures; `FnEvaluator` from `evaluator`/`composite_evaluator`/`run_evaluator`, closures need `Fut: 'static`), `IntoEvaluations`, the `Task` trait (`-> impl Future + Send`, so task closures may borrow), `ExperimentItem`, `ExperimentOptions`, `ExperimentResult::format`, `RegressionError`, and the Python-compatible `python_isoformat` / `python_float_repr`.
- `src/otel/experiment.rs` — `LangfuseTracer::run_experiment` / `DatasetWithItems::run_experiment`: items via `buffered(max_concurrency)`; per item `experiment-item-run` → `experiment-item-task` (task runs in `experiment_context`) and `experiment-item-evaluation` → evaluator spans. Experiment attributes live in the crate-private `ExperimentAttributes` of `PropagatedState` (forces `sdk-experiment`, never baggage); the run span is backfilled with `inherited_attributes`. Experiment ID derivation, local item IDs (SHA-256 of Python's `json.dumps`, through `PythonFormatter`) and scores via `tracer.score`.
- `src/batch_evaluation.rs` — `LangfuseClient::run_batched_evaluation`: cursor loop over `observations.list_with_options` (crate-private, `CallOptions` with retries and 60 s timeout), dedup by ID, `Mapper` trait, `RunState` counters, `BatchEvaluationResumeToken` (serde), scores via `client.score` with the observation's environment.

**Integrations and blocking client:**
- `src/openai.rs` (feature `openai`) — `OpenAI<C: Config>` wrapping `async_openai::Client` with a `LangfuseTracer`; `Chat`/`Embeddings`/`Responses` handles with per-call `with_*`. Extraction is a port of Python's `langfuse/openai.py` on the JSON of requests and responses (`to_json` round-trips through text so `f32` stay short); `TracedStream` accumulates chunks (`ChatStream`, `ResponsesStream`) and finishes on end or drop. Pure functions are unit-tested in the module.
- `src/blocking/` (feature `blocking`) — `mod.rs`: `Runtime` (multi-thread, one worker, `shutdown_background` on drop), `blocking_methods!`, `BlockingPages`/`BlockingItems`, the non-generated `LangfuseClient` methods and the blocking `LangfuseTracer` (`Deref` to the async one). `api.rs` is generated by `scripts/generate_blocking.py` (one module per `src/api` file: `pub use` of its items, copied imports, the wrapper struct and `blocking_methods!`, plus the `LangfuseClient` struct and `assemble`). Never edit it by hand.

**Tools** (`src/tools/`): `YamlTool` — standalone YAML utility (read/write/merge/validate/frontmatter extraction) using `serde_norway` (maintained `serde_yaml` fork; `serde_yml` was dropped for RUSTSEC-2025-0068). Not part of the API client.

## Conventions

- All API methods return `Result<T, LangfuseError>`.
- Every list method returning `Paginated` / `CursorPaginated` gets a `<method>_pages` companion (params by value, `paginate_pages` / `paginate_cursor`), its params get `impl_page_query!` / `impl_cursor_query!`, and the route is added to the wiring tests in `tests/pagination_tests.rs`.
- Use the HTTP helper that matches the spec response: a JSON body needs a JSON helper; 204 needs a no-content helper (`request` deserializes every 2xx body).
- Adding a new resource requires: model structs in `src/models/`, API client in `src/api/`, both registered in their `mod.rs`, a field and its construction in `LangfuseClient` (`src/lib.rs`), the field in `client_with_custom_config` (`tests/config_tests.rs`), a `tests/api_<resource>_tests.rs` wiremock file and serde tests for its enums (`tests/serde_new_resources_tests.rs`, or `tests/serde_unstable_tests.rs` for unstable APIs).
- Public option structs (`GetPromptOptions`, `ScoreQueueOptions`, `TracingOptions`, `PropagatedAttributes`, `GetDatasetOptions`, `ExperimentOptions`, `BatchEvaluationOptions`, `RequestOptions`) are `#[non_exhaustive]` with public fields and one `with_<field>` builder per field; add a builder with every new field. Outside the crate (tests, examples, README, doc tests) build them with `Default::default().with_*(..)` (or `new(required)` for `ExperimentOptions::new(name)` and `BatchEvaluationOptions::new(mapper)`), never struct literals. The same goes for `Evaluation`, `EvaluatorInput` and `LocalExperimentItem` (constructors plus `with_*`).
- After adding or changing a public method of an API client, run `python3 scripts/generate_blocking.py` (`tests/blocking_tests.rs` fails otherwise).
- The macros crate and the main crate share the version: bump both, and the `=x.y.z` requirement on `langfuse-rust-sdk-macros`, together.
- Record user-visible changes in `CHANGELOG.md`.
